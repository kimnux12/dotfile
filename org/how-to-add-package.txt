In-Buffer Setting (YAML metadata)요약
(출처: https://orgmode.org/manual/In_002dbuffer-Settings.html)

In-buffer settings start with ‘#+’, followed by a keyword, a colon, one or more spaces, and then a word for each setting. Org accepts multiple settings on the same line. Org also accepts multiple lines for a keyword. This manual describes these settings throughout. A summary follows here.

C-c C-c activates any changes to the in-buffer settings. Closing and reopening the Org file in Emacs also activates the changes.

‘#+ARCHIVE: %s_done::’
    Sets the archive location of the agenda file. The corresponding variable is org-archive-location.

‘#+CATEGORY’
    Sets the category of the agenda file, which applies to the entire document.

‘#+COLUMNS: %25ITEM ...’

org-mode에서 link 편집



Links in org-mode by default are displayed as “descriptive” links, meaning they hide their target URLs (or a destination in general). While this looks great, it makes it a bit tricky to figure out how you can edit their URL. There are two easy options:

    Just press C-c C-l (org-insert-link) while your point is within a link and you’ll be prompted to edit its URL in the minibuffer. You can use the same command to create new links (when your point is not on an existing link).

    You can convert the “descriptive” links to “literal” links1 by invoking the command M-x org-toggle-link-display. You can also toggle between the two display modes for links via the mode’s menu (under “Hyperlinks”).

And that’s all I have for you today. Admitted, I keep forgetting about this all the time, as I rarely use org-mode, which is the reason I’ve decided to write this short article. Keep hacking!

Doom Emacs에서 표현식 평가하기
1. *scratch* 버퍼에서 평가하기

scratch 버퍼에서 표현식을 평가하는 방법은 다음과 같습니다:

    Doom Emacs 클라이언트 실행:
        터미널에서 Emacs 클라이언트를 실행합니다:

        bash

    GDK_BACKEND=x11 emacsclient -c -a ''

*scratch* 버퍼 열기:

    SPC b s를 눌러 *scratch* 버퍼를 엽니다. *scratch* 버퍼는 기본적으로 Emacs가 시작될 때 열리는 버퍼입니다.

표현식 입력:

    *scratch* 버퍼에 다음 코드를 입력합니다:

    emacs

        (featurep 'xwidget-internal)

    표현식 평가:
        커서를 표현식 끝에 놓고 C-x C-e (Ctrl + x를 누르고 Ctrl + e를 누름)로 표현식을 평가합니다.
        그러면 미니버퍼에 t 또는 nil이 출력됩니다. t는 Xwidgets가 지원됨을 의미하고, nil은 지원되지 않음을 의미합니다.

2. M-: (Eval Expression)로 평가하기

Doom Emacs에서 M-: (Alt + :)를 사용하여 표현식을 직접 평가할 수도 있습니다:
          ***** SPC + : 이 평가창을 직접 호출한다 *****

    미니버퍼 호출:
        SPC :를 눌러 미니버퍼를 엽니다. 이는 M-x와 동일한 기능을 합니다.
        미니버퍼에 eval-expression을 입력하고 Enter를 누릅니다.
        또는 직접 M-: (Alt + :)를 누릅니다. 이는 eval-expression 명령어를 호출합니다.

    표현식 입력:
        미니버퍼에 (featurep 'xwidget-internal)을 입력하고 Enter를 누릅니다.
        결과가 미니버퍼에 출력됩니다. t는 Xwidgets가 지원됨을 의미하고, nil은 지원되지 않음을 의미합니다.

요약

Doom Emacs에서 (featurep 'xwidget-internal) 표현식을 평가하려면 전체 표현식을 괄호로 감싸야 하며, *scratch* 버퍼나 eval-expression 명령어(M-:)를 사용하여 평가할 수 있습니다. 이를 통해 Emacs가 Xwidgets를 지원하는지 여부를 확인할 수 있습니다.

hugo 디렉토리와 git orphan branch 연결방법

새로운 폴더를 만들어서 기존의 Git 저장소에 있는 orphan 브랜치와 연결하려면 다음 단계를 따릅니다. 이 방법은 새로운 폴더를 만들고, 그 폴더에서 기존 Git 저장소를 클론한 후 orphan 브랜치를 체크아웃하는 방식입니다.

    새 폴더 생성:
    원하는 위치에 새 폴더를 만듭니다.

    bash

cd new-folder

기존 Git 저장소를 새 폴더에 클론합니다. repository-url은 기존 Git 저장소의 URL입니다.

bash

점(.)을 사용하여 현재 디렉토리(new-folder)에 저장소를 클론합니다.

클론한 저장소에서 orphan 브랜치를 체크아웃합니다. 예를 들어, orphan 브랜치의 이름이 new-orphan-branch라면:

bash

    git checkout new-orphan-branch

이 단계를 요약하면 다음과 같습니다:

bash

# 1. 새 폴더 생성
mkdir new-folder

# 2. 기존 Git 저장소 클론

# 3. orphan 브랜치 체크아웃
git checkout new-orphan-branch

이제 new-folder 폴더에서 기존 Git 저장소의 new-orphan-branch 브랜치를 사용할 수 있습니다. 이 상태에서 새로운 파일을 추가하거나 기존 파일을 수정하고 커밋할 수 있습니다.

repository-url은 기존 Git 저장소의 URL을 의미합니다. 이는 클론하려는 원격 저장소의 위치를 가리키며, HTTPS URL이나 SSH URL을 사용할 수 있습니다. 예를 들어, GitHub에서 호스팅되는 저장소의 경우 URL은 다음과 같은 형식일 수 있습니다:

클론한 저장소에서 orphan 브랜치를 체크아웃합니다. 예를 들어, orphan 브랜치의 이름이 new-orphan-branch라면:

기존 원격 저장소를 추가합니다. <repository-url>은 기존 Git 저장소의 URL입니다.

orphan 브랜치를 생성합니다. 예를 들어 new-orphan-branch라는 이름의 orphan 브랜치를 생성합니다.

현재 작업 디렉토리의 파일을 모두 스테이징합니다.

bash

org문서에 이미지 삽입하는 방법

Hugo를 사용하는 경우, 이미지를 Hugo의 콘텐츠 디렉토리에 위치시키고 Org 문서에서 해당 경로를 참조해야 합니다. 일반적으로 Hugo의 콘텐츠 디렉토리는 static 디렉토리입니다.

    이미지 파일을 Hugo의 static 디렉토리에 저장:
    예를 들어, 이미지 파일을 static/images/ 디렉토리에 저장합니다.

    Org 문서에서 이미지 참조:
    Org 문서에서 이미지를 참조할 때는 static 디렉토리 이후의 경로를 사용합니다.

org

[[file:images/your-image.png]]

또는 다음과 같이 HTML 속성을 사용할 수 있습니다:

org

#+CAPTION: This is an example image with Hugo
#+ATTR_HTML: :width 300px :align center
[[file:images/your-image.png]]

예제

다음은 Hugo 사이트에 이미지를 포함하는 전체적인 예제입니다:

    Hugo 프로젝트 구조:

arduino

my-hugo-site/
├── content/
│   └── post/
│       └── my-post.org
└── static/
    └── images/
        └── example-image.png

    my-post.org 파일 내용:

org

#+TITLE: My Post
#+DATE: 2024-07-13

This is an example post with an image.

#+CAPTION: Example Image
#+ATTR_HTML: :width 300px :align center
[[file:images/example-image.png]]

이 예제를 통해 이미지를 Hugo 사이트에서 올바르게 표시할 수 있습니다.
추가 팁

    이미지 링크: 웹에서 이미지를 직접 링크하여 사용할 수도 있습니다.

org

[[http://example.com/path/to/image.png]]

    Figure Block 사용: 이미지에 설명을 추가하는 Figure 블록을 사용할 수도 있습니다.

org

#+CAPTION: This is an example image with a figure block
#+ATTR_HTML: :width 300px :align center
#+ATTR_LATEX: :width 0.5\textwidth
[[file:images/example-image.png]]

이와 같이 설정을 통해 Org 문서에서 이미지를 적절하게 삽입하고 Hugo 사이트에 반영할 수 있습니다. 추가적인 설정이나 문제가 발생하면 더 자세한 내용을 알려주세요.

org문서의 tag를 md의 tag로 유지하는 방법
org문서의 tags를 마크다운의 tag를 변환하는 방법?
ChatGPT

Org 문서의 태그를 Markdown 형식의 태그로 변환하려면, Org 문서에서 사용된 태그를 Hugo와 같은 Markdown 지원 시스템에서 인식할 수 있도록 변환해야 합니다. 특히 Hugo에서는 특정 형식을 사용하여 태그를 관리할 수 있습니다. 이를 위해 몇 가지 방법을 사용할 수 있습니다.
1. Org 문서의 태그 형식

Org 문서에서 태그는 헤딩 끝에 콜론(:)으로 구분하여 사용됩니다:

org

* Heading 1      :tag1:tag2:
** Heading 2     :tag3:

2. Hugo에서 태그 사용

Hugo에서는 일반적으로 문서의 프론트 매터(front matter)에서 태그를 정의합니다. YAML, TOML, 또는 JSON 형식으로 작성할 수 있습니다. 예를 들어, YAML 형식의 태그는 다음과 같습니다:

yaml

---
title: "My Post"
date: 2024-07-13
tags: ["tag1", "tag2"]
---

3. Org 문서에서 Hugo로 변환

Org 문서의 태그를 Hugo의 프론트 매터로 변환하기 위해 다음과 같은 단계를 따를 수 있습니다:
3.1. Org 문서에서 태그 추출

Org 문서의 헤딩에서 태그를 추출합니다. 예를 들어, 다음과 같은 Org 문서가 있다고 가정합니다:

org

#+TITLE: My Post
#+DATE: 2024-07-13
* Introduction :intro:example:
Content of the introduction.
* Conclusion :summary:example:
Content of the conclusion.

3.2. 태그를 프론트 매터로 변환

태그를 Hugo의 프론트 매터 형식으로 변환합니다. 태그를 수동으로 추출하여 프론트 매터에 추가할 수 있습니다:

org

#+TITLE: My Post
#+DATE: 2024-07-13
#+HUGO_TAGS: intro, example, summary

* Introduction
Content of the introduction.
* Conclusion
Content of the conclusion.

3.3. Emacs Lisp 코드로 자동화

Emacs Lisp 코드를 사용하여 Org 문서의 태그를 자동으로 추출하고 Hugo 프론트 매터에 추가할 수 있습니다. 다음은 간단한 Emacs Lisp 예제입니다:

emacs

(defun my-org-to-hugo-tags ()
  "Extract tags from Org headings and add them to Hugo front matter."
  (interactive)
  (goto-char (point-min))
  (let (tags)
    (while (re-search-forward "^\\*+.*?\\(:[[:alnum:]_@#%:]+:\\)$" nil t)
      (let ((tag-string (match-string 1)))
        (setq tags (append tags (split-string tag-string ":" t)))))
    (goto-char (point-min))
    (if (re-search-forward "^#\\+HUGO_TAGS:.*$" nil t)
        (replace-match (concat "#+HUGO_TAGS: " (mapconcat 'identity tags ", ")))
      (insert (concat "#+HUGO_TAGS: " (mapconcat 'identity tags ", ") "\n")))))

(add-hook 'org-mode-hook
          (lambda ()
            (local-set-key (kbd "C-c C-h") 'my-org-to-hugo-tags)))

이 코드는 Org 문서에서 태그를 추출하여 #+HUGO_TAGS: 줄에 추가합니다. Org 모드에서 C-c C-h를 눌러 실행할 수 있습니다.
최종 예제

Org 문서가 다음과 같다면:

org

#+TITLE: My Post
#+DATE: 2024-07-13
* Introduction :intro:example:
Content of the introduction.
* Conclusion :summary:example:
Content of the conclusion.

Emacs Lisp 코드를 실행한 후:

org

#+TITLE: My Post
#+DATE: 2024-07-13
#+HUGO_TAGS: intro, example, summary

* Introduction
Content of the introduction.
* Conclusion
Content of the conclusion.

이제 이 Org 문서는 Hugo에서 태그로 인식될 수 있습니다.

이 방법을 사용하면 Org 문서의 태그를 Hugo의 프론트 매터 형식으로 쉽게 변환할 수 있습니다. 추가적인 질문이나 도움이 필요하면 말씀해 주세요!

ox-hugo를 사용해 변환할 때, org  문서의 줄바꿈을 유지하는 방법?
ChatGPT

Ox-Hugo를 사용해 Org 문서를 Markdown으로 변환할 때 줄바꿈을 유지하려면 몇 가지 설정을 통해 가능합니다. 기본적으로 Org 모드와 Markdown 변환은 줄바꿈을 다르게 처리할 수 있기 때문에, 설정을 통해 줄바꿈을 유지하도록 조정해야 합니다.
1. Org 모드의 줄바꿈 설정

Org 모드에서 줄바꿈을 유지하려면 org-export-preserve-breaks 변수를 설정해야 합니다. 이 변수는 줄바꿈을 유지할지 여부를 결정합니다.

emacs

(setq org-export-preserve-breaks t)

이 설정은 줄바꿈을 유지하도록 합니다. 그러나 Ox-Hugo를 사용할 때 추가적인 설정이 필요할 수 있습니다.
2. Ox-Hugo 설정

Ox-Hugo는 기본적으로 Hugo에서 잘 동작하도록 다양한 설정을 지원합니다. 줄바꿈을 유지하기 위해서는 org-hugo-auto-set-lastmod와 같은 추가적인 설정을 사용합니다.
Emacs 설정 파일에 추가

Emacs 설정 파일(init.el 또는 .emacs)에 다음과 같이 설정을 추가합니다:

emacs

;; Org 모드에서 줄바꿈을 유지하도록 설정
(setq org-export-preserve-breaks t)

;; ox-hugo 설정 추가
(require 'ox-hugo)
(setq org-hugo-auto-set-lastmod nil)

3. Org 문서에서 직접 설정

Org 문서 내에서 줄바꿈을 유지하도록 설정할 수도 있습니다. 문서의 맨 위에 다음과 같은 설정을 추가합니다:

org

#+OPTIONS: \n:t

이 설정은 Org 문서에서 줄바꿈을 유지하도록 합니다.
4. 예제

다음은 설정이 적용된 Org 문서의 예제입니다:
설정 파일 (init.el 또는 .emacs)

emacs

;; Org 모드에서 줄바꿈을 유지하도록 설정
(setq org-export-preserve-breaks t)

;; ox-hugo 설정 추가
(require 'ox-hugo)
(setq org-hugo-auto-set-lastmod nil)

Org 문서

org

#+TITLE: My Post
#+DATE: 2024-07-13
#+OPTIONS: \n:t

This is the first line.
This is the second line.

이제 Ox-Hugo를 사용해 변환하면 줄바꿈이 유지된 Markdown 문서를 얻을 수 있습니다.
5. Markdown 결과 확인

변환된 Markdown 문서는 다음과 같이 줄바꿈이 유지됩니다:

markdown

---
title: "My Post"
date: 2024-07-13
---

This is the first line.
This is the second line.

이렇게 하면 Ox-Hugo를 사용해 Org 문서를 변환할 때 줄바꿈을 유지할 수 있습니다. 추가적인 설정이나 문제가 있다면 더 자세히 설명해 주시면 좋겠습니다.
